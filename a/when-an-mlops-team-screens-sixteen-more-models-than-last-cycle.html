WHEN AN MLOPS TEAM SCREENS SIXTEEN MORE MODELS THAN LAST CYCLE

In this article ❧ A growth figure means something only when the base is named. Companies compare volume from one cycle to the next to judge capacity, staffing, and the pace of demand, and the same count reads as progress or as noise depending on what it sits against. This problem shows how a comparison between two period counts collapses into one figure, and how that figure can be packaged as a tool that outlives the single case.

The Problem

An MLOps team screened 80 candidate models during last year's evaluation cycle. This year it screened 96.

By what percentage did the number of models screened increase over last year?

  • a) 20 %
  • b) 16.6 %
  • c) 83 %
  • d) 5 %
Click to Reveal the Answer

Correct Answer: a) 20 % ✅

Math Solution

The extra volume is 16 models, so the task is to divide that change by last year's 80, the base the question names. Since 16 / 80 reduces to 1 / 5, the increase is 20 %.

Every point of growth here is worth 0.8 models, which is why a swing of 16 lands on a round 20 %.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Prior cycle volume: 80 models screened, the base
  2. Current cycle volume: 96 models screened
  3. Change: 96 minus 80 = 16 models
  4. Change over base: 16 / 80 = 1 / 5
  5. Part of one: 1 ÷ 5 = 0.20
  6. Stated as a percent: 0.20 = 20 %
  7. Cross check: 96 / 80 = 1.20, which stands 20 % above the base

Justified Proof

Setup. Let p be the prior cycle volume, so p = 80 models. Let c be the current cycle volume, so c = 96 models. Let r be the increase as a part of one, measured against p. The question names last year as the reference, so the governing equation is c = p + rp, that is 96 = 80 + 80r.

  1. The extra volume is 16 models. Subtraction property of equality. Subtract 80 from both sides of 96 = 80 + 80r, which leaves 16 = 80r.
  2. r equals the quotient 16 / 80. Division property of equality. Divide both sides of 16 = 80r by 80.
  3. 16 / 80 reduces to 1 / 5. Cancellation, b times a over b equals a. Write 16 = 16(1) and 80 = 16(5), then cancel the shared factor 16.
  4. r = 0.20. Definition of a rational number as a quotient. Carry out 1 ÷ 5 = 0.20.
  5. r = 20 %. Definition of percent as parts per hundred. 0.20 = 20 / 100, which is written 20 %.
  6. The base is p and not c. FLAG. This move rests on reading the question, which asks for the change relative to last year, rather than on a named theorem.
  7. An independent route returns the same r. Substitution. From c = p(1 + r), divide by p to get 96 / 80 = 6 / 5 = 1.20, so 1 + r = 1.20 and r = 0.20.

Verification. Put r = 0.20 back into c = p + rp. Then 80(0.20) = 16 and 80 + 16 = 96. The right side equals the stated current volume, so both sides match.

Answer. The MLOps team screened 20 % more candidate models this cycle than last, which is option a.

Historical Background

Rates per hundred entered commercial practice through Roman lending, where the monthly charge known as the centesima fixed one part in a hundred and gave later merchants a shared unit. Italian trade manuals of the fifteenth century carried the habit into bookkeeping, setting profit against outlay so that two ventures of different size could be ranked on one scale. Statistical offices of the nineteenth century then turned the same comparison into the period over period growth rate for prices, output, and population, and firms now apply that inherited form to counts as ordinary as the models a team puts through evaluation.

Python Version

The script holds the base in one place and reports the growth between any two period counts, e.g. tickets opened, licenses sold, or seats activated.

# What this does: works out how much bigger this year's number is, as a percent.
# Where it came from: an MLOps team screened 80 candidate models one year and 96 the next.
# The math idea: find the extra amount, then see what part of the old number it is.
# You type in: last year's count and this year's count.
# It prints: the percent increase from last year to this year.

# This function does the math.
def percent_increase(prior_count, current_count):
    # Find how many more models were screened this year.
    extra = current_count - prior_count
    # See what part of last year's count that extra amount is, then turn it into a percent.
    return (extra / prior_count) * 100

# Tell the reader what we will figure out.
print("Let's find the percent increase in models screened.")

# Ask for last year's count.
prior_count = float(input("Models screened last cycle: "))

# Ask for this year's count.
current_count = float(input("Models screened this cycle: "))

# Do the math.
result = percent_increase(prior_count, current_count)

# Show a whole number when the answer has no decimals.
result = int(result) if result.is_integer() else round(result, 2)

# Print the answer with words that fit the scenario.
print("Increase in models screened versus last cycle:", str(result) + " %")

Paste it into a Python session, enter 80 and then 96, and it returns 20 %.

# Percent Increase Calculator

This skill takes two counts from two periods and reports how much the later count grew over the earlier one, stated as a percentage of the earlier count. It expects one number for the prior period and one number for the current period. It returns a single percentage figure phrased in the wording of the scenario the user described.

---

## Dependencies

None. Basic arithmetic covers the whole calculation.

---

## Inputs

- **Prior period count**. The quantity recorded in the earlier period. Any number greater than zero, since it serves as the base of the comparison.
- **Current period count**. The quantity recorded in the later period. Any number, whole or decimal.

---

## Steps

### Step 1 — Collect the two counts

Ask the user for the prior period count and the current period count, one at a time, using prompts that name the scenario rather than generic labels. Accept decimals as well as whole numbers.

### Step 2 — Validate the base

Check that the prior period count is not zero. If it is zero, stop and tell the user that a percentage increase has no base to compare against, then ask for a nonzero prior count.

### Step 3 — Find the change

Subtract the prior period count from the current period count. This gives the extra amount added between the two periods. A negative result means the quantity fell rather than grew.

### Step 4 — Express the change as a share of the base

Divide the change by the prior period count. This gives the change as a part of one. Multiply by 100 to state it as a percentage.

### Step 5 — Format the figure

If the percentage lands on a whole number, show it without decimals. Otherwise round it to two decimals.

### Step 6 — Report the result

Print the percentage with wording that names the quantity and the comparison, e.g. "Increase in models screened versus last cycle, 20 %". If the result is negative, phrase it as a decrease rather than an increase. Do not print the intermediate change or the division result unless the user asks.

---

## Example Trigger Prompts

- "We screened 80 models last year and 96 this year, how much did that grow?"
- "Support tickets went from 240 to 300, what is the percent increase?"
- "Tell me the year over year growth in licenses sold"
- "Our headcount rose from 45 to 52, by what percentage?"

The skill file states the same procedure as instructions rather than code, so the calculation runs inside a conversation with no Python session open. The result stays tied to the scenario, which means the figure arrives named rather than bare.
