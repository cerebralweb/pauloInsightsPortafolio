WHY A CLOUD TEAM CANNOT SPREAD 35 PATCH WINDOWS ACROSS THE YEAR

In this article ❧ Operations teams assume that a large pool of time slots keeps their maintenance windows apart. That assumption fails faster than most planners expect, because collisions depend on the pairs of assets being compared, not on the size of the pool alone. This problem shows how counting the opposite event turns an unmanageable set of cases into one product, and how Python turns that logic into a reusable tool.

The Problem

A cloud operations team manages 35 virtual machines. Each machine receives one of the 365 days of the year for its annual security patch, and every day is equally likely. Leap days are ignored, and each machine is assigned independently of the others.

What is the probability that at least two of the 35 machines are patched on the same day?

  • a) 9.59%
  • b) 18.56%
  • c) 50.73%
  • d) 81.44%
Click to Reveal the Answer

Correct Answer: d) 81.44% ✅

Math Solution

Counting the shared days directly means counting many separate cases, so the route runs through the opposite event. Count the assignments where all 35 days differ, divide by the whole sample space, then subtract that result from 1.

35 machines form 595 distinct pairs, and every pair is a chance to collide, which is why 35 out of 365 understates the risk by a factor of eight.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Sample space: each machine has 365 options, so 36535 assignments exist
  2. No match count: 365 × 364 × 363 × ... × 331, the options shrinking by one per machine
  3. Last factor: 365 − 34 = 331
  4. No match probability: (365 × 364 × ... × 331) / 36535 = 0.1856
  5. Complement: 1 − 0.1856 = 0.8144
  6. Conclusion: about 81.44% of such schedules put two or more machines on the same day

Each step below names the property that licenses it, then shows that property acting on the numbers.

Setup

Let n be the machines, d the available days, S the sample space size, N the count of assignments with all days distinct, and P the probability that at least two machines share a day. The constraint is that a shared day and all days distinct are complementary events.

Notation

  • n is the number of machines, 35.
  • d is the number of available patch days, 365.
  • S is the number of equally likely assignments of days to machines, fixed in Step 1.
  • N is the number of assignments in which all machines hold distinct days, fixed in Step 2.

  • P(Ac) is the probability of Ac, fixed in Step 4.

Solution

Step 1 — Multiplication principle of counting

Property. Multiplication principle. If a choice has x options and a later independent choice has y options, the pair has xy options, extending to any finite number of choices.

Inference. S = (365)(365)...(365) = 36535, with 35 factors.

Step 2 — Permutation count

Property. Permutation count. P(d, n) = d(d − 1)(d − 2)...(d − n + 1), the options shrinking by one at each successive choice.

Inference. N = P(365, 35) = (365)(364)(363)...(331), with 365 − 35 + 1 = 331 the last factor.

Step 3 — Classical definition of probability

Property. Classical probability. For a finite Ω with equally likely outcomes, P(E) = |E| / |Ω|.

Inference. P(Ac) = N / S = (365)(364)...(331) / 36535. From lines 1 and 2.

Step 4 — Cancellation law

Property. Cancellation law. For y ≠ 0, (yx) / y = x, so a product over a product may be split into factors.

Inference. P(Ac) = (365/365)(364/365)...(331/365) ≈ 0.1856. From line 3.

Step 5 — Complement rule

Property. Complement rule. A ∪ Ac = Ω and A ∩ Ac = ∅ ⇒ P(A) = 1 − P(Ac).

Inference. P(A) = 1 − (365)(364)...(331) / 36535. From line 3.

Step 6 — Subtraction property of equality

Property. Subtraction property of equality. x = y ⇒ m − x = m − y.

Inference. P(A) = 1 − 0.1856 ≈ 0.8144. From lines 4 and 5.

Verification

P(A) + P(Ac) ≈ 0.8144 + 0.1856 = 1.0000. The two events exhaust Ω, so the sum must be 1. Both sides match.

A second check on the structure. With n = 3 and d = 3, Step 1 gives S = 33 = 27, Step 2 gives N = (3)(2)(1) = 6, and Step 5 gives P(A) = 1 − 6/27 = 21/27 ≈ 0.7778, which matches a direct enumeration of the 27 assignments.

Answer

P(A) = 1 − (365)(364)...(331) / 36535 ≈ 0.8144. The chance that at least two of the 35 machines are patched on the same day is about 81.44%.

Properties in Action

Seven stages, in bar model form. Stages 4, 6 and 7 carry sliders, so the same structure can be tested at any size. Set 23 machines against 365 days to watch the shared bar cross half the whole bar.

Historical Background

The question first circulated among actuaries and insurance clerks, who needed to know how often two policies or two claims would fall on the same date, and found the answer far higher than their intuition allowed. Richard von Mises put the problem into print in 1939 while working on the foundations of probability, and it spread through statistics teaching as a demonstration that intuition misjudges collisions.

The same count now governs scheduling and storage in computing. Engineers use it to size identifiers so that two records do not receive the same key, and operations teams use it to decide whether randomly assigned maintenance windows need a scheduler to keep them apart.

Python Version

The script takes any fleet size and any pool of days, so the same logic covers patch windows, hash keys, or shift rosters.

# What this does: works out the chance that two or more machines get the same patch day.
# Where it came from: a cloud team gave each of 35 machines one patch day out of 365.
# The math idea: count the chance of no match, then take it away from 1.
# You type in: how many machines and how many days are available.
# It prints: the chance that at least two machines share a day.

# This function does the math.
def chance_of_shared_day(machines, days):
    # If there are more machines than days, a match is certain.
    if machines > days:
        return 1.0
    # Start the no match chance at 1, then shrink it machine by machine.
    no_match = 1.0
    # Each machine must avoid the days already taken, so one fewer day each time.
    for taken in range(machines):
        no_match = no_match * (days - taken) / days
    # Take the no match chance away from 1.
    return 1 - no_match

# Tell the reader what we will figure out.
print("Let's find the chance that two or more machines share a patch day.")

# Ask how many machines there are.
machines = int(input("Number of machines: "))

# Ask how many patch days are available.
days = int(input("Number of possible patch days: "))

# Do the math.
result = chance_of_shared_day(machines, days)

# Turn the result into a percent and round it.
percent = round(result * 100, 2)

# Print the answer with words that fit the scenario.
print("Chance that at least two machines share a patch day:", str(percent) + "%")

Run it in a terminal, enter 35 and 365, and it returns 81.44%.

A shorter version uses the standard library, where math.perm counts the no match arrangements in one call.

# What this does: works out the chance that two or more machines get the same patch day.
# Where it came from: a cloud team gave each of 35 machines one patch day out of 365.
# The math idea: count the chance of no match, then take it away from 1.
# You type in: how many machines and how many days are available.
# It prints: the chance that at least two machines share a day.

# Bring in a tool that counts arrangements.
import math

# This function does the math.
def chance_of_shared_day(machines, days):
    # If there are more machines than days, a match is certain.
    if machines > days:
        return 1.0
    # Count the ways to give every machine a different day.
    no_match_ways = math.perm(days, machines)
    # Count all the ways to give every machine any day.
    all_ways = days ** machines
    # Take the no match chance away from 1.
    return 1 - no_match_ways / all_ways

# Tell the reader what we will figure out.
print("Let's find the chance that two or more machines share a patch day.")

# Ask how many machines there are.
machines = int(input("Number of machines: "))

# Ask how many patch days are available.
days = int(input("Number of possible patch days: "))

# Do the math.
result = chance_of_shared_day(machines, days)

# Turn the result into a percent and round it.
percent = round(result * 100, 2)

# Print the answer with words that fit the scenario.
print("Chance that at least two machines share a patch day:", str(percent) + "%")

Both versions return the same value, and the second one matches the written formula factor for factor.
