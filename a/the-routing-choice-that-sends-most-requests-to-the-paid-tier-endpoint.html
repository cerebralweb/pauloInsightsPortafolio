THE ROUTING CHOICE THAT SENDS MOST REQUESTS TO THE PAID TIER ENDPOINT

In this article ❧ Traffic in a service never spreads itself evenly, and the shape of the routing layer decides where the load lands. Teams that size every endpoint alike discover the imbalance in production, when one service saturates while its neighbours sit idle. This problem shows how a share of traffic can be estimated from logged traces, checked against the share the topology predicts, and turned into a reusable tool.

The Problem

One at a time, inference requests enter the routing graph of an agentic AI service. Four endpoints terminate the graph, A, B, C, and D. At each node where the router must pick a next hop, assume every available hop is equally likely. A request never returns to a node it already passed. From the entry node the request takes either the left branch to node 2 or the right branch to node 3. Node 2 offers three hops, left to A, straight to B, right to C. Node 3 offers two hops, left to C, right to D. Endpoint C serves the paid model tier, and endpoints A, B, and D serve no paid traffic.

Fifty traces were logged, each recorded as two hops where L stands for left, R for right, and S for straight. The log holds 6 traces of LL, 8 of LS, 10 of LR, 11 of RL, and 15 of RR. Using these traces, what is the estimated probability that a request reaches endpoint C?

  • a) 0.12
  • b) 0.25
  • c) 0.42
  • d) 0.30

Correct Answer: c) 0.42 ✅

Math Solution

Endpoint C has two inbound routes, so the success traces are LR and RL, and adding their counts gives 21. Dividing 21 by the 50 logged traces returns 0.42, close to the 5/12 the topology predicts.

C leads not because any hop favours it, but because it is the only endpoint fed by two hops, and one of them is the wide slice from the node with fewer choices.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Success traces: LR and RL, the two inbound routes to endpoint C
  2. Count of LR: 10 traces
  3. Count of RL: 11 traces
  4. Total successes: 10 + 11 = 21 traces
  5. Estimated share: 21 / 50 = 0.42
  6. Theoretical share: (1/2)(1/3) + (1/2)(1/2) = 1/6 + 1/4 = 5/12 = 0.417
  7. Gap: 0.42 − 0.417 = 0.003, well inside the sampling error for 50 traces
  8. Remaining endpoints: A 0.12, B 0.16, D 0.30, against predictions of 0.167, 0.167, and 0.250
  9. Conclusion: the equal share model of 0.25 per endpoint fails, and the model built from the topology holds

The Proof

The estimate above comes from the log. The value it is tested against comes from the topology, and that value can be established step by step, every move carrying the name of the property that licenses it.

Claim

Given the routing graph, where the entry node offers two hops, node 2 offers three hops, node 3 offers two hops, and every hop available at a node is equally likely, the probability that a request reaches endpoint C equals 5/12, and the four endpoints are therefore not equally likely.

Notation

  • P(X) is the probability of event X, a number between 0 and 1.
  • Ω is the sample space, the set of the five complete routes through the graph.
  • L₁ is the event that the first hop goes left, so the request arrives at node 2.
  • R₁ is the event that the first hop goes right, so the request arrives at node 3.
  • L₂, S₂, R₂ are the events that the second hop goes left, straight, or right, the subscript 2 marking the second hop.
  • A, B, C, D are the events that the request ends at that endpoint.
  • P(X | Y) is the probability of X once Y has occurred, read the probability of X given Y.
  • ∩ reads and, the joint occurrence of two events.
  • ∪ reads or, the occurrence of at least one of two events.
  • ∅ is the empty set, an event that cannot occur.
  • ≠ reads is not equal to, and > reads is greater than.
  • ⇒ reads implies, and ⇔ reads if and only if.
  • k is the number of hops available at a node, 2 at the entry node, 3 at node 2, and 2 at node 3.
  • x, y are any events, used to state a property in general form.

Method

Direct proof. The claim is a value for P(C), reachable by a chain from the uniform hop assumption through the multiplication rule and the addition rule.

Step 1 — Classical definition of probability on a finite equiprobable space

Property. Classical probability. If a trial has k equally likely outcomes, each outcome x has P(x) = 1/k.

Inference. At the entry node k = 2, so P(L₁) = 1/2 and P(R₁) = 1/2.

Step 2 — Classical definition of probability, applied at the second node

Property. Classical probability, as in Step 1.

Inference. At node 2, k = 3, so P(R₂ | L₁) = 1/3. At node 3, k = 2, so P(L₂ | R₁) = 1/2.

Step 3 — Definition of an event by its routes

Property. Event decomposition. An event is the set of outcomes that realize it, so x ⇔ the union of its outcomes.

Inference. C = (L₁ ∩ R₂) ∪ (R₁ ∩ L₂).

Step 4 — General multiplication rule

Property. General multiplication rule. P(x ∩ y) = P(x)P(y | x).

Inference. P(L₁ ∩ R₂) = (1/2)(1/3) = 1/6. From lines 1 and 2.

Step 5 — General multiplication rule, again

Property. General multiplication rule, as in Step 4.

Inference. P(R₁ ∩ L₂) = (1/2)(1/2) = 1/4. From lines 1 and 2.

Step 6 — Definition of mutually exclusive events

Property. Mutually exclusive events. x ∩ y = ∅ ⇔ x and y cannot both occur.

Inference. L₁ ∩ R₁ = ∅, so (L₁ ∩ R₂) ∩ (R₁ ∩ L₂) = ∅. From line 3.

Step 7 — Addition rule for mutually exclusive events

Property. Addition rule. x ∩ y = ∅ ⇒ P(x ∪ y) = P(x) + P(y).

Inference. P(C) = 1/6 + 1/4 = 2/12 + 3/12 = 5/12. From lines 4, 5, and 6.

Step 8 — Normalization axiom with finite additivity

Property. Normalization and finite additivity. P(Ω) = 1, and for a partition of Ω the probabilities of its parts sum to 1.

Inference. P(A) = (1/2)(1/3) = 1/6, P(B) = (1/2)(1/3) = 1/6, P(D) = (1/2)(1/2) = 1/4, and 1/6 + 1/6 + 5/12 + 1/4 = 2/12 + 2/12 + 5/12 + 3/12 = 1. From lines 1, 2, and 7.

Step 9 — Trichotomy

Property. Trichotomy. For any x, y exactly one of x < y, x = y, x > y holds.

Inference. 5/12 > 3/12 = 1/4, so P(C) ≠ 1/4. From lines 7 and 8.

Conclusion

P(C) = 5/12, and since 5/12 ≠ 1/4 the four endpoints are not equally likely. QED.

Historical Background

Estimating a probability by running trials instead of deriving it took its modern form in 1946, when Stanislaw Ulam, recovering from an illness and playing solitaire, asked what fraction of layouts could be won and concluded that dealing many hands beat working out the combinatorics. He raised the idea with John von Neumann, and the two ran the first large simulations of neutron diffusion on ENIAC in 1948.

Nicholas Metropolis named the method after the casino in Monaco and published the first account of it with Ulam in 1949. The practice spread from weapons physics into queueing theory, insurance pricing, and eventually capacity planning for computing systems, where a traffic share is read off a log of trials rather than solved in closed form.

Python Version

The script turns the trace counts into an estimated share for the paid tier endpoint and compares it against the share the routing graph predicts, so it works for any log, not only for the fifty traces shown in the problem.

Option 1, pure Python

# What this does: works out how often requests reached the paid tier endpoint.
# Where it came from: logged traces from a routing graph with four endpoints, A, B, C and D.
# The math idea: count the hits, divide by the total, then compare with the expected share.
# You type in: how many traces reached each of the four endpoints.
# It prints: the share that reached the paid tier and how it compares with the expected share.

# This function does the math.
def paid_tier_share(hits_a, hits_b, hits_c, hits_d):
    # Add up all the traces.
    total = hits_a + hits_b + hits_c + hits_d
    # If nothing was logged, there is nothing to divide by.
    if total == 0:
        return None, 0
    # Divide the paid tier hits by the total.
    return hits_c / total, total

# Tell the reader what we will figure out.
print("Let's find how often requests reached the paid tier endpoint C.")

# Ask for the traces that ended at each endpoint.
hits_a = int(input("Traces that reached A: "))
hits_b = int(input("Traces that reached B: "))
hits_c = int(input("Traces that reached C, the paid tier: "))
hits_d = int(input("Traces that reached D: "))

# Do the math.
share, total = paid_tier_share(hits_a, hits_b, hits_c, hits_d)

# Stop early if no traces were entered.
if share is None:
    print("No traces were logged, so there is nothing to estimate.")
else:
    # The graph predicts 5 out of 12 for this endpoint.
    expected = 5 / 12
    # Round both numbers to three decimals so they are easy to read.
    share = round(share, 3)
    expected = round(expected, 3)
    # Find how far the logs sit from the expected share.
    gap = round(share - expected, 3)
    # Print the answer with words that fit the scenario.
    print("Traces logged:", total)
    print("Share that reached the paid tier:", share)
    print("Share the routing graph predicts:", expected)
    print("Gap between the logs and the prediction:", gap)

Open a terminal, type python, paste the script, and enter the four counts. It returns the logged share, the predicted share, and the gap between them, which is the number an operations team watches for drift.

Option 2, with the fractions module

The fractions module keeps the predicted share as the exact value 5/12 instead of a rounded decimal, so the comparison stays honest for any number of traces.

# What this does: works out how often requests reached the paid tier endpoint.
# Where it came from: logged traces from a routing graph with four endpoints, A, B, C and D.
# The math idea: count the hits, divide by the total, then compare with the expected share.
# You type in: how many traces reached each of the four endpoints.
# It prints: the share that reached the paid tier, as a fraction and as a decimal.

# Bring in a tool that keeps fractions exact.
from fractions import Fraction

# This function does the math.
def paid_tier_share(hits_a, hits_b, hits_c, hits_d):
    # Add up all the traces.
    total = hits_a + hits_b + hits_c + hits_d
    # If nothing was logged, there is nothing to divide by.
    if total == 0:
        return None, 0
    # Keep the share as an exact fraction.
    return Fraction(hits_c, total), total

# Tell the reader what we will figure out.
print("Let's find how often requests reached the paid tier endpoint C.")

# Ask for the traces that ended at each endpoint.
hits_a = int(input("Traces that reached A: "))
hits_b = int(input("Traces that reached B: "))
hits_c = int(input("Traces that reached C, the paid tier: "))
hits_d = int(input("Traces that reached D: "))

# Do the math.
share, total = paid_tier_share(hits_a, hits_b, hits_c, hits_d)

# Stop early if no traces were entered.
if share is None:
    print("No traces were logged, so there is nothing to estimate.")
else:
    # The graph predicts 5 out of 12 for this endpoint.
    expected = Fraction(5, 12)
    # Work out the gap, still as an exact fraction.
    gap = share - expected
    # Print the answer with words that fit the scenario.
    print("Traces logged:", total)
    print("Share that reached the paid tier:", share, "which is", round(float(share), 3))
    print("Share the routing graph predicts:", expected, "which is", round(float(expected), 3))
    print("Gap between the logs and the prediction:", round(float(gap), 3))

Entering 6, 8, 21 and 15 returns the share as 21/50 against the predicted 5/12, which is the same comparison the first script makes in decimals.
