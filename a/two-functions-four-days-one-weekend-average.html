TWO FUNCTIONS, FOUR DAYS, ONE WEEKEND AVERAGE

In this article ❧ Capacity planning often rests on a single average that hides several moves. A base level, a fixed shortfall, a fractional lift, and a percent lift can each land on a different day, yet the number a team reports is their mean. This article traces how that average is built one algebraic move at a time, then packages the same logic as a small program and a reusable skill.

The Equation Step by Step

Let c be the base, with c equal to 2,000. Each function has a Saturday value and a Sunday value. The weekend average is the mean of the two.

Checkout Average

The following sequence shows how the checkout average is derived:

  1. Start: a = [ c + c(1 + 0.15) ] / 2
  2. Distribute c across (1 + 0.15): a = [ c + (c + 0.15c) ] / 2
  3. Combine like terms, c + c = 2c: a = [ 2c + 0.15c ] / 2
  4. Distribute division by 2: a = 2c/2 + 0.15c/2
  5. Simplify: a = c + 0.075c
  6. Substitute c = 2,000: a = 2,000 + 150
  7. Result: a = 2,150

Search Average

The following sequence shows how the search average is derived:

  1. Start: a = [ (c − 230) + c(1 + 1/4) ] / 2
  2. Distribute c across (1 + 1/4): a = [ (c − 230) + (c + 0.25c) ] / 2
  3. Combine like terms: a = [ 2.25c − 230 ] / 2
  4. Substitute c = 2,000: a = [ 4,500 − 230 ] / 2
  5. Subtract: a = 4,270 / 2
  6. Result: a = 2,135

The Proof

Mode. Compute. Setup. Let c be the base, checkout Saturday, fixed at 2,000. Checkout Sunday is c raised by 15 percent. Search Saturday is 230 below c. Search Sunday is c raised by one quarter. Each weekend average is the mean of the two daily counts for that function.

  1. Distributive law. A times the quantity b plus d equals A times b plus A times d. Checkout Sunday is c plus 0.15c, since c times the quantity 1 plus 0.15 spreads c across both terms.
  2. Distributive law, as in step 1. The checkout weekend sum is 2c plus 0.15c. Adding checkout Saturday c to c plus 0.15c gives c plus c plus 0.15c, and c plus c is 2c.
  3. Distribution over addition for division. The quantity x plus y over 2 equals x over 2 plus y over 2. The checkout average is 2c over 2 plus 0.15c over 2. The divisor 2 spreads across the two numerator terms.
  4. Multiplicative identity. 2c over 2 is c, since dividing by 2 undoes the factor 2. The checkout average is c plus 0.075c, which is 2,000 plus 150, so 2,150.
  5. Additive inverse and closure. Subtracting 230 is adding negative 230, and the result is a well defined integer. Search Saturday is 1,770.
  6. Distributive law, as in step 1. Search Sunday is 2,500, since c times the quantity 1 plus one quarter is c plus 0.25c, which is 2,000 plus 500.
  7. Arithmetic mean. The mean of two values is their sum divided by 2. The search average is 2,135, since 1,770 plus 2,500 is 4,270 and 4,270 over 2 is 2,135.

Two distributions carry the whole result. First c spreads across its parentheses to build each day. Then the division by 2 spreads across the sum to take the mean.

Verification. Checkout, 2,150 times 2 is 4,300, which is 2,000 plus 2,300. Search, 2,135 times 2 is 4,270, which is 1,770 plus 2,500. Both means reproduce their daily sums. Answer. Search averaged 2,135 per day and checkout averaged 2,150 per day, matching option a.

The program below uses the standard library helper statistics.mean, which states the averaging step by name and keeps the intent visible.

# What this does: works out the weekend daily average for two functions.
# Where it came from: two serverless functions ran over Saturday and Sunday.
# The math idea: build each day's count, then average the two days.
# You type in: the base count, the shortfall, the fraction rise, the percent rise.
# It prints: the weekend average for search and for checkout.

# Bring in a ready made average helper from Python's own toolbox.
from statistics import mean

# This function does all the math and hands back both averages.
def weekend_averages(base, shortfall, fraction_rise, percent_rise):
    # Checkout Saturday is the base count.
    checkout_sat = base
    # Checkout Sunday is the base raised by the percent.
    checkout_sun = base * (1 + percent_rise / 100)
    # Search Saturday is the base minus the shortfall.
    search_sat = base - shortfall
    # Search Sunday is the base raised by the fraction.
    search_sun = base * (1 + fraction_rise)
    # Average each function's two days with the helper.
    return mean([search_sat, search_sun]), mean([checkout_sat, checkout_sun])

# Tell the reader what we will figure out.
print("Let's find the weekend daily average for two functions.")

# Ask for the base count.
base = float(input("Base invocations (checkout Saturday): "))

# Ask for the shortfall for search Saturday.
shortfall = float(input("Search Saturday shortfall: "))

# Ask for the fraction rise for search Sunday. Type 0.25 for one quarter.
fraction_rise = float(input("Search Sunday fraction rise (e.g. 0.25): "))

# Ask for the percent rise for checkout Sunday. Type 15 for 15 percent.
percent_rise = float(input("Checkout Sunday percent rise (e.g. 15): "))

# Do the math.
search_avg, checkout_avg = weekend_averages(base, shortfall, fraction_rise, percent_rise)

# Show whole numbers cleanly when the result has no decimals.
search_avg = int(search_avg) if float(search_avg).is_integer() else round(search_avg, 2)
checkout_avg = int(checkout_avg) if float(checkout_avg).is_integer() else round(checkout_avg, 2)

# Print the answers with words that fit the scenario.
print("Search weekend average:", search_avg)
print("Checkout weekend average:", checkout_avg)

Run it in the terminal, type 2000, 230, 0.25, and 15, and it returns search 2,135 and checkout 2,150.

# Weekend Two Function Average

This skill takes a base count and three adjustments, builds four daily values across two days for two items, then averages each item's two days. It asks for the base count, a shortfall, a fraction increase, and a percent increase, and it returns the weekend average for each of the two items.

---

## Dependencies

None. Plain arithmetic only. An optional averaging helper from Python's standard library can state the mean step by name, but it is not required.

---

## Inputs

- **Base count**. The Saturday value for the first item. A number.
- **Shortfall**. How far the second item's Saturday value sits below the base. A number.
- **Fraction increase**. The fractional rise applied to the base for the second item's Sunday value. Enter 0.25 for one quarter.
- **Percent increase**. The percent rise applied to the base for the first item's Sunday value. Enter 15 for 15 percent.

---

## Steps

### Step 1 — Collect the four inputs

Ask for the base count, the shortfall, the fraction increase, and the percent increase. Treat all four as numbers that may carry decimals.

### Step 2 — Build the first item's two days

Set the first item's Saturday value equal to the base count. Set its Sunday value to the base count raised by the percent increase, so base times the quantity 1 plus the percent over 100.

### Step 3 — Build the second item's two days

Set the second item's Saturday value to the base count minus the shortfall. Set its Sunday value to the base count raised by the fraction increase, so base times the quantity 1 plus the fraction.

### Step 4 — Average each item

For each item, add its Saturday and Sunday values and divide by 2. This gives two weekend averages, one per item.

### Step 5 — Clean and report

If an average lands on a whole number, show it without decimals. Otherwise round to two decimals. Report both averages with text that names each item, e.g. search weekend average and checkout weekend average.

---

## Example Trigger Prompts

- "Average two functions across the weekend from a base count and a couple of adjustments"
- "One item is a percent above the base, the other starts below it then rises by a quarter, give me both weekend averages"
- "Turn my base, shortfall, fraction, and percent into two daily averages"
- "Work out the Saturday and Sunday mean for each of my two services"

---

## Quality Check Before Delivering

- [ ] All four inputs were collected as numbers
- [ ] The first item's Sunday value uses the percent, the second item's Sunday value uses the fraction
- [ ] The shortfall was subtracted from the base for the second item's Saturday value only
- [ ] Each average is the sum of that item's two days divided by 2
- [ ] Whole number results show without decimals, others round to two
- [ ] Both averages are labeled by item in the final output

The Dialogue

The reasoning above came out of a short back and forth about which move distributed what. It is reproduced here because the confusion it clears up is common.

Paulo. I set a as the average and c as the base. I wrote a equals 2c over 2 plus c times 0.15 over 2. Did I distribute c into two elements to be added?

Claude. The two elements come from the numerator. The two day sum is c plus c times 1.15, which is c plus c plus 0.15c, so 2c plus 0.15c. Then you divide that by 2.

Paulo. So I distributed 2 and 0.15 into c?

Claude. Not both. The 0.15 came from distributing c across 1 plus 0.15, giving c plus 0.15c. The 2 did not come from distribution. It came from adding the two c terms, c plus c is 2c. That is combining like terms.

Paulo. If I say c times the quantity 2 plus 0.15, am I distributing c into the addition of 2 and 0.15?

Claude. That form is the factored form, the starting point. Distribution is the move that multiplies c through, c times 2 plus c times 0.15, giving 2c plus 0.15c. Going backward, from 2c plus 0.15c to c times the quantity 2 plus 0.15, is factoring.

Paulo. So before, when you checked that 2c over 2 is 2,000 and 0.15c over 2 is 150, I expanded c into 2 plus 0.15?

Claude. No. That line divided the numerator. What spread there was the division by 2 across 2c and 0.15c. c stayed inside each term.

Paulo. But that is not the true order. To arrive at that numerator I first distributed c into 2c plus 0.15c, and then I reasoned that I had to divide by 2.

Claude. You are right. I skipped your first step. You built the numerator by distributing c, c times the quantity 2 plus 0.15 equals 2c plus 0.15c. Then you distributed the division by 2 across that sum. Two distributions, in your order. First c across the parentheses. Then division by 2 across the numerator.
