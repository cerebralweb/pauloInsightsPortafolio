WHAT A DATA ANALYST READS FIRST DECIDES WHICH MODEL VERSION SHIPS

In this article ❧ Release decisions rest on a typical result rather than an average one, because a few failed evaluation runs pull an average away from what a system actually does. Reporting the typical result means knowing which position in a sorted list of measurements to read, and that position depends on how many measurements there are. This problem shows how a small counting rule decides whether one measurement or two carry the answer, and how Python turns that rule into a reusable check.

The Problem

A platform director asked a data analyst to review two sets of accuracy scores from the evaluation runs of two model versions before release. Set A contains 35 scores. Set B contains 36 scores.

After sorting each set from lowest to highest, the director asked where the median of each set is located.

  • a) at position 18 and at the average of positions 18 and 19
  • b) at the average of positions 17 and 18 and at the average of positions 18 and 19
  • c) at the mean of each group
  • d) at the value that occurs most frequently in each group
Click to Reveal the Answer

Correct Answer: a) position 18 for Set A, and the average of positions 18 and 19 for Set B ✅

Math Solution

An odd count leaves one score exactly in the middle, found by adding one to the count and halving the result, which places the median of Set A at position 18. An even count leaves no single middle score, so the two central positions, found by halving the count and taking the next position, are averaged, which gives positions 18 and 19 for Set B.

The count alone decides whether the median is one measurement or the average of two.

Step-by-Step Breakdown

The following sequence shows how the answer is derived:

  1. Count for Set A: 35 scores, an odd count, so one position sits at the center
  2. Median position for Set A: (35 + 1) / 2 = 18
  3. Balance check for Set A: 17 scores below position 18 and 17 scores above it
  4. Count for Set B: 36 scores, an even count, so no single position sits at the center
  5. Median positions for Set B: 36 / 2 = 18, and 18 + 1 = 19
  6. Median value for Set B: the average of the scores at positions 18 and 19
  7. Balance check for Set B: 17 scores below position 18 and 17 scores above position 19
  8. Answer: option a, position 18 for Set A and the average of positions 18 and 19 for Set B

Historical Background

Ranking measurements rather than averaging them entered practice through disputes about faulty instruments. Edward Wright, writing on navigation errors in 1599, advised that a navigator facing compass readings that disagreed should take the middle one, since a single bad reading would spoil any combined figure. Formal treatment came much later. The 19th century story has four moves.

Laplace gives it standing. In the 1818 supplement to his work on probability, Laplace compared two ways of fitting observations. One minimised squared errors, which yields the average. The other minimised absolute errors, which yields the middle observation. He called the second the method of situation and credited its origin to Boscovich, who had used it around 1757 on meridian arc measurements. Laplace worked out how much the middle observation varies from sample to sample and set that against the average, which turned a practical shortcut into an estimator with known behaviour.

Cournot names it. In 1843 Cournot used the term valeur médiane for the value that splits a distribution into two halves of equal probability. His argument concerned lopsided distributions, where the average sits away from where most of the data lies. That is the term still in use.

Fechner spreads it. Fechner worked with the Zentralwert from the 1870s in his measurement studies, and his collective measurement treatise, published in 1897 after his death, carried the median into German statistical practice.

Galton carries it into English. Galton had written of the middlemost value; by the early 1880s he was writing median. He folded it into his percentile scheme, where the middle value sits at the halfway point of a drawn curve and can be read off with no arithmetic at all, which suited his graphical methods. Edgeworth defended it as an estimator in the same decade, and Pearson later tied it to the average and the most frequent value in lopsided distributions.

Why it took so long. The average had calculus behind it, since squared deviations differentiate cleanly, and that is what made the method of least squares tractable after Gauss and Legendre. Absolute deviations do not behave that way. The median resisted the analytic tools of the period, so it arrived late and by a different route.

Python Version

The script asks only how many scores each set contains, then names the position to read, so it answers the same question for any two sets whatever their size.

# What this does: tells you where the middle score sits in each of two sorted sets of scores.
# Where it came from: a director reviewed two model versions before release. One version had 35 accuracy scores, the other had 36, and she asked where the middle score was in each set.
# The math idea: the median is the middle value once the scores are in order. An odd count has one middle score. An even count has two, so you average them.
# You type in: how many scores are in each set.
# It prints: the spot to read in each sorted set to get the middle score.

# This function works for any count of scores, big or small, odd or even.
def where_is_the_middle(score_count):
    # An odd count leaves one score exactly in the middle.
    if score_count % 2 == 1:
        spot = (score_count + 1) // 2
        return "spot " + str(spot)
    # An even count leaves two scores in the middle, so we average them.
    first = score_count // 2
    second = first + 1
    return "the average of spots " + str(first) + " and " + str(second)

# Tell the reader what we will figure out.
print("Let's find the middle score in each of two sets of model accuracy scores.")

# Ask how many scores the first model version produced.
count_a = int(input("How many scores in set A? "))

# Ask how many scores the second model version produced.
count_b = int(input("How many scores in set B? "))

# Work out where the middle sits in each set.
answer_a = where_is_the_middle(count_a)
answer_b = where_is_the_middle(count_b)

# Print the answer with words that fit the scenario.
print("Set A has", count_a, "sorted scores. Read the middle score at", answer_a + ".")
print("Set B has", count_b, "sorted scores. Read the middle score at", answer_b + ".")

Run it in a terminal, type each count when prompted, and it prints the position to read for each set, including whether two positions have to be averaged.

# Median Position Finder

This skill answers a positional question rather than a value question. Given how many values a sorted set contains, it reports which position in that ordered list holds the median, and whether one position or two positions are involved. It accepts a count for a single set or counts for several sets, and returns a plain statement per set naming the position to read. It never needs the values themselves.

---

## Dependencies

No libraries or external tools are required. The work is arithmetic on the count of values.

---

## Inputs

- **Count of values per set**: A whole number greater than zero for each set under review, e.g. 35 for the first set and 36 for the second. Labels for the sets are optional. If the user supplies the values instead of a count, count them and continue.

---

## Steps

### Step 1 — Confirm what is being asked

Establish that the request is about the position of the median, not its value. If the user supplied actual values and wants the median value, sort the values and report the value as well as the position. Otherwise report the position only.

### Step 2 — Validate each count

Check that each count is a whole number of one or more. If a count is zero, negative, or not a whole number, say that no median position exists for that set and ask for a corrected count. Do not guess.

### Step 3 — Classify each count as odd or even

Divide the count by two and look at the remainder. A remainder of one means the count is odd. A remainder of zero means it is even. The classification drives everything that follows.

### Step 4 — Locate the position for an odd count

If the count is odd, add one to the count and halve the result. That single position holds the median. Confirm the balance before reporting, since the number of values below that position must equal the number above it.

### Step 5 — Locate the two positions for an even count

If the count is even, halve the count to get the lower position, then add one to get the upper position. The median is the average of the values at those two positions. Confirm that the number of values below the lower position equals the number above the upper position.

### Step 6 — Report each set in plain language

For each set, state the count and then the position to read. Use one sentence per set. For an odd count, name the single position. For an even count, name both positions and state that their values are averaged. If the user is comparing sets, keep the sets in the order they were given so the two answers can be read side by side.

### Step 7 — Match answer choices when they exist

If the user supplied answer options, compare the computed positions against each option and name the matching one. If nothing matches, say so and show the computed positions rather than selecting the nearest option.

## Example Trigger Prompts

- "I sorted 35 test scores. Which one is the middle score?"
- "Where is the median in a list of 36 values?"
- "One group has 35 results and the other has 36. Where is the median of each?"
- "Do I average two numbers to get the median, or just take one?"
- "Which position holds the middle value once the list is in order?"
