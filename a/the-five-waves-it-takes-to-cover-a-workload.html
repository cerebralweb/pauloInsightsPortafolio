THE FIVE WAVES IT TAKES TO COVER A WORKLOAD

In this article ❧ Cloud capacity planning turns on a single question, how fast a system grows once it starts. When each round of work spawns more work of the same shape, the total climbs by multiplying, not by adding, and a team that plans for steady growth will underprovision fast. This problem shows how a doubling cascade reaches a target in surprisingly few rounds, and how a running accumulator captures that growth in a form Python can reuse.

The Problem

A cloud team runs a serverless job that must process 50 records. One orchestrator starts the job and invokes 2 functions. In the next wave, each of those functions invokes 2 more functions. Every wave doubles the number of new functions the same way. The job runs until at least 50 functions have been invoked, one per record. The workload holds 50 records.

How many waves are needed to cover all 50?

  • a) 6
  • b) 11
  • c) 5
  • d) 1
Click to Reveal the Answer

Correct Answer: c) 5 ✅

Math Solution

Write the total after a wave as the current wave plus an accumulator, where the accumulator holds every earlier wave. Each wave adds its functions to that accumulator, and each new wave is the previous wave times 2. Track the running total until it clears 50.

The total after n waves equals 2 to the power (n plus 1), minus 2, so five waves reach 62 while four reach only 30.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Wave 1: current 2, accumulator 0, total 2
  2. Wave 2: current 4, accumulator 2, total 6
  3. Wave 3: current 8, accumulator 6, total 14
  4. Wave 4: current 16, accumulator 14, total 30
  5. Wave 5: current 32, accumulator 30, total 62
  6. First crossing: wave 4 gives 30, below 50; wave 5 gives 62, at or above 50
  7. Answer: 5 waves

The Accumulator Proof

This proof justifies the form the reader wrote, 2 to the power n plus t, and names the properties behind it. There is no closed form for t. The accumulator stays as a running total, added one wave at a time.

The wave size at wave n is 2 to the power n. This is the current wave. The accumulator, t sub n, is the total of every wave before wave n. It is a value carried forward and updated each round, not a formula.

Claim. The total after n waves is T(n) equals 2 to the power n, plus t sub n. The smallest n with T(n) at least 50 is n equals 5.

Method. Direct evaluation. Set where the accumulator starts, state how it updates, run the rounds, then take the first crossing.

Proof Steps

  1. Split the total. By associativity of addition, terms in a sum regroup without changing the total, so T(n) equals the current wave 2 to the power n, plus the rest, t sub n.
  2. Set the start. By the definition of the accumulator, nothing has been done before the first wave, so t sub 1 equals 0.
  3. State the update. By the recurrence, each round absorbs the wave that just finished, so t at n plus 1 equals t sub n, plus 2 to the power n.
  4. Run the rounds. Wave 1 total 2, wave 2 total 6, wave 3 total 14, wave 4 total 30, wave 5 total 62. Each accumulator is the previous line's total.
  5. Confirm the crossing. By monotonicity, every wave size is positive, so the total only rises. Wave 4 gives 30, below 50; wave 5 gives 62, at or above 50.
  6. Take the least n. By the well ordering principle, the waves that clear 50 form a nonempty set of whole numbers, and its least element is 5.

Verification. At wave 5 the current wave is 2 to the power 5, which is 32, and the accumulator is 30. Their sum is 62, which satisfies the rule. At wave 4 the sum is 30, which fails it. So 5 is the smallest n.

Conclusion. The form 2 to the power n plus t holds by associativity, with t carried by the recurrence from a start of 0. Running the rounds and taking the first crossing gives n equals 5. QED.

Historical Background

Growth by repeated doubling has shaped how people reason about scale for a long time, from old fables about grains multiplying on a chessboard to compound interest in early banking. In the twentieth century the same shape reappeared in technology, when Gordon Moore observed in 1965 that the number of transistors on a chip was doubling at a steady pace, a pattern later named Moore's Law.

The lesson for business is constant across those eras. When each unit produces more units of its own kind, totals reach large numbers in few steps, which is why capacity planning under doubling looks calm for several rounds and then overwhelms a fixed budget.

Python Version

The first script keeps a running accumulator and adds one wave at a time until the total clears the target, which mirrors the original reasoning exactly.

# What this does: finds how many waves a doubling job needs to cover all records.
# Where it came from: a serverless job starts 2 functions, and each wave doubles the new functions.
# The math idea: keep a running total, add each wave, stop when the total reaches the target.
# You type in: the number of records that must be covered.
# It prints: how many waves are needed.

# This function does the math.
def waves_needed(records):
    # The running total of functions started so far. Nothing yet.
    total = 0
    # Count the waves as we go.
    wave = 0
    # The size of the next wave. The first wave starts 2 functions.
    wave_size = 2
    # Keep adding waves until the total reaches the target.
    while total < records:
        # Move to the next wave.
        wave = wave + 1
        # Add this wave's functions to the running total.
        total = total + wave_size
        # The next wave is twice as big.
        wave_size = wave_size * 2
    # Hand back the wave count and the final total.
    return wave, total

# Tell the reader what we will figure out.
print("Let's find how many doubling waves cover all the records.")

# Ask for the number of records.
records = int(input("Records to cover: "))

# Do the math.
wave, total = waves_needed(records)

# Print the answer with words that fit the scenario.
print("Waves needed:", wave)
print("Functions started by then:", total)

The second script skips the loop with a closed form. Since the total after n waves is 2 to the power (n plus 1) minus 2, a base 2 logarithm pulls the exponent out directly, which is faster for very large targets.

# What this does: finds how many waves a doubling job needs to cover all records.
# Where it came from: a serverless job starts 2 functions, and each wave doubles the new functions.
# The math idea: the total after n waves is 2 to the power (n+1) minus 2, solved straight for n.
# You type in: the number of records that must be covered.
# It prints: how many waves are needed.

# Bring in the math tools for logs and rounding up.
import math

# This function does the math.
def waves_needed(records):
    # The total after n waves is 2 to the power (n+1) minus 2.
    # We need that total to reach the target, so 2 to the power (n+1) must reach target plus 2.
    # Take the log base 2 to pull the exponent down, then round up to the next whole wave.
    exponent = math.ceil(math.log2(records + 2))
    # The exponent is n plus 1, so subtract 1 to get the wave count.
    wave = exponent - 1
    # Work out the total functions started by then.
    total = 2 ** (wave + 1) - 2
    # Hand back the wave count and the final total.
    return wave, total

# Tell the reader what we will figure out.
print("Let's find how many doubling waves cover all the records.")

# Ask for the number of records.
records = int(input("Records to cover: "))

# Do the math.
wave, total = waves_needed(records)

# Print the answer with words that fit the scenario.
print("Waves needed:", wave)
print("Functions started by then:", total)

Run either in a terminal, type 50 at the prompt, and both return 5 waves with 62 functions started by then.

A Short Dialogue

The questions below trace how the code maps back to the accumulator, and how the closed form handles the exponent.

Q. In the code, is wave_size the same as my accumulator t?

A. No. wave_size is the current wave, 2 to the power n. Your t is the accumulator, which the code holds in total before this wave is added.

Q. In wave_size = wave_size * 2, does times 2 represent the base in my 2 to the power n?

A. Yes. Multiplying by 2 advances the power one step, from 2 to the power n to 2 to the power n plus 1.

Q. What does math.ceil do?

A. It rounds up to the next whole number. 4.2 becomes 5, and 4.0 stays 4. A wave count must be whole, so a result of 5.3 rounds up to 6.

Q. The docs say it returns an integral. What does integral mean here?

A. A whole number. It hands back 5, not 5.0. This is not the calculus meaning of the word.

Q. Does the base 2 logarithm give the power of 2 that yields its argument?

A. Yes. log base 2 of 64 is 6, because 2 to the power 6 is 64. The logarithm undoes the exponent.

Q. Why records + 2 and not just records?

A. The rule is 2 to the power n plus 1, minus 2, at least records, which rearranges to 2 to the power n plus 1, at least records plus 2. Dropping the plus 2 undercounts. At 64 records it would return 5 waves and 62 functions, short of 64.

Q. Does 2 to the power 6, minus 2, really equal 62?

A. Yes. 2 to the power 6 is 64, and 64 minus 2 is 62. The minus 2 comes off after the power, not out of the exponent. 2 to the power 6 minus 2 in the exponent would be 16, a different thing.
