THE CASCADING ARITHMETIC OF VOUCHERS TURNED INTO CLIENT PROJECTS

In this article ❧ Capacity planning turns on a single division, how many full commitments a fixed pool of resources can cover. Cloud and operations teams meet it whenever a stock of prepaid capacity runs up against a fixed draw per project, and the quotient rarely lands on a whole number. This problem shows how dividing a total by a fixed requirement separates the projects a pool can fully honor from the one left underfunded.

The Problem

A cloud operations lead holds 5 storage vouchers, each worth 0.5 TB. Provisioning one client project consumes 1.5 TB.

How many full projects can she provision with all her vouchers, and will one project run short on storage?

  • a) More than 1 and less than 2, yes
  • b) Less than 1, yes
  • c) 2, yes
  • d) 1, yes
Click to Reveal the Answer

Correct Answer: a) More than 1 and less than 2, yes ✅

Math Solution

The vouchers hold 5 × 0.5 = 5/2 TB. Setting 5/2 = x(3/2) and solving gives x = 5/3, which is one full project plus 2/3 of a project. The leftover is 1 TB, under the 1.5 TB a project needs.

The project count is total storage divided by storage per project, and the remainder is what leaves the last project short.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Total storage: 5 × 0.5 = 5/2 = 2.5 TB
  2. Project equation: 5/2 = x(3/2), where x is the project count
  3. Solve for x: x = (5/2)(2/3) = 5/3
  4. Whole part: 5/3 = 1 + 2/3, so 1 full project
  5. Leftover: 2/3 of a project, which is 1 TB, under 1.5 TB
  6. Conclusion: more than 1 and fewer than 2 projects, and one runs short

The Proof

Each step names the property that licenses it and shows that property acting on the numbers.

Setup. Five vouchers at 0.5 TB each. One project draws 1.5 TB. Let x be the number of projects, a positive rational.

5(1/2) = x(3/2)

Step 1 — Fraction multiplication rule. (a/1)(c/d) = ac/d. So 5(1/2) = 5/2, giving 5/2 = x(3/2).

Step 2 — Multiplication property of equality. If a = b then ca = cb. Multiply each side by 2/3, giving (2/3)(5/2) = (2/3)x(3/2).

Step 3 — Multiplicative inverse property. (c/d)(d/c) = 1. Since (2/3)(3/2) = 1, the right side becomes x(1).

Step 4 — Multiplicative identity property. x(1) = x. So x = (2/3)(5/2).

Step 5 — Cancellation law. (b·a)/(b·c) = a/c for nonzero b. So x = 10/6 = (2·5)/(2·3) = 5/3.

Step 6 — Division algorithm. a = bk + r with 0 ≤ r < b. Since 5 = 3·1 + 2, we get 5/3 = 1 + 2/3, so 1 full project with 2/3 left.

Step 7 — Trichotomy of order. Exactly one holds, less than, equal, or greater than. Since 1 < 5/3 < 2 and 2/3 > 0, one project runs short.

Verification. x(3/2) = (5/3)(3/2) = 15/6 = 5/2 = 2.5 TB, which matches the total storage 5(1/2).

A Dialog Toward the Right Equation

Student. I worked it out. The lead has 5 halves of a TB, and 5/2 splits into 3/2 plus 2/2. So the answer is 5/2.

Mentor. Your split is fine, but check the units. 5/2 is TB. The question asks for projects. Those are not the same thing.

Student. Then what does 3/2 plus 2/2 tell me?

Mentor. It tells you the storage, cut into pieces. The 3/2 is one project worth of TB. The 2/2 is what is left. Useful, but still TB.

Student. So I need an equation that solves for projects, not TB.

Mentor. Right. Write the total as a number of projects. The lead has 5(1/2) TB. Each project is 3/2 TB. So how many projects x fit in that total?

Student. That gives 5(1/2) = x(3/2).

Mentor. Now solve it.

Student. 5/2 = x(3/2), so x = (5/2)(2/3) = 5/3. One and two thirds of a project.

Mentor. And the two thirds?

Student. Not a full project. So one full project and one that runs short. More than 1 and fewer than 2. Option a.

Historical Background

Dividing a fixed supply into equal shares and living with the remainder is one of the oldest jobs in arithmetic. Scribes in ancient Egypt handled it daily, splitting loaves and jars of beer among work crews, and the Rhind Mathematical Papyrus records these divisions as sums of unit fractions rather than a single tidy quotient. Estate managers and quartermasters across the ancient world reasoned the same way, since a ration or an allotment that does not come out even forces a choice about the piece that is left over.

Python Version

This function takes any pool and draw size and returns the full commitments, whether a partial one remains, and the exact quotient, so it works for storage, budget, or any resource measured against a fixed draw.

from fractions import Fraction

def project_count(vouchers, tb_per_voucher, tb_per_project):
    total = Fraction(vouchers) * Fraction(tb_per_voucher)
    quotient = total / Fraction(tb_per_project)
    full = quotient.numerator // quotient.denominator
    remainder = quotient - full
    short = remainder > 0
    return full, short, quotient

full, short, q = project_count(5, Fraction(1, 2), Fraction(3, 2))
print(full, short, q)  # 1 True 5/3

Run it with the values above and it returns 1 full project, a short project flagged True, and the exact count 5/3.
