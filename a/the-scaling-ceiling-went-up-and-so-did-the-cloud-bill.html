THE SCALING CEILING WENT UP, AND SO DID THE CLOUD BILL

In this article ❧ A cloud invoice reports what a service consumed, never what it used to consume. Growth rates arrive attached to the new figure, and the team that wants to judge a configuration change has to recover the baseline that the growth was measured against. This problem shows why a reported increase must be undone by division rather than by subtraction, and how a short Python function turns that reversal into a reusable tool.

The Problem

Emilio runs the cloud account for a small product team. He raised the autoscaling ceiling on the API service to improve response times. The service consumed 287.50 compute hours last month, 15% more than the month before.

How many compute hours did the service consume the month before?

  • a) 241
  • b) 250
  • c) 260
  • d) 255
Click to Reveal the Answer

Correct Answer: b) 250 ✅

Math Solution

The earlier month is the base, so the later month equals that base multiplied by 1.15. Recovering the base therefore means dividing 287.50 by 1.15, which gives 250.

Taking 15% off the new figure yields 244.375, because 15% of 287.50 is larger than 15% of the base it was applied to.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Name the unknown: x is the compute hours in the earlier month
  2. Write the relationship: x + 0.15x = 287.50, so 1.15x = 287.50
  3. Isolate the base: x = 287.50 / 1.15 = 250
  4. Verify: 250 × 0.15 = 37.50, and 250 + 37.50 = 287.50
  5. Read the business fact: the higher ceiling added 37.50 compute hours

Historical Background

Reasoning in hundredths is older than the word percent. In imperial Rome, Augustus levied the centesima rerum venalium, a tax of one hundredth on goods sold at auction, and later a duty of a twenty fifth on the sale of slaves. Auction clerks recorded the amount the buyer paid, which already contained the duty, so separating the duty from the hammer price meant working backward from a combined total. Italian merchant houses formalized the same reversal in the fifteenth century, when commissions and interest were quoted per cento and ledgers had to distinguish principal from the total that carried it.

Python Version

The script recovers the base value behind any figure that already includes a stated growth rate, which makes it reusable for cloud spend, headcount, or unit volumes.

def base_before_growth(current_value, growth_rate_percent):
    """Return the value a growth rate was applied to.

    current_value: the figure that already includes the growth
    growth_rate_percent: the reported increase, e.g. 15 for 15%
    """
    factor = 1 + growth_rate_percent / 100
    return current_value / factor


if __name__ == "__main__":
    base = base_before_growth(287.50, 15)
    print(round(base, 2))
    print(round(287.50 - base, 2))

Run it with python base_before_growth.py and it returns 250.0, the earlier month, followed by 37.5, the hours the change added.
