THE HALF FUNCTION A CLOUD BUDGET CAN NEVER DEPLOY

In this article ❧ Cloud spending rarely reduces to a single price. Most budgets carry a fee that applies once and a rate that scales with volume, and the split decides how many units a team can afford before the money runs out. This problem shows how a fixed cost, a variable rate, and a whole number rule combine into a hard ceiling, and how Python can turn that logic into a reusable tool.

The Problem

A cloud provider runs a promotion. Deploying a serverless function costs $4,000 each. A one time platform setup costs $2,000 no matter how many functions you deploy. A platform lead at Maria Goeppert Analytics wants to launch a batch of functions for an internal automation project. Her budget is $400,000.

How many functions can she deploy?

  • a) 99
  • b) 99 and a half functions
  • c) 100 functions
  • d) 99 and a half functions, plus a half function on the house
Click to Reveal the Answer

Correct Answer: a) 99 ✅

Math Solution

Total cost follows 2,000 + 4,000n. Subtract the fixed 2,000 from the 400,000 budget, then divide the remaining 398,000 by 4,000 to get 99.5. A function cannot ship in halves, so the count rounds down to 99.

The fixed fee is spent before a single function exists, so only the leftover budget divides by the unit price.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Remove the fixed cost: 400,000 − 2,000 = 398,000
  2. Divide by the unit price: 398,000 ÷ 4,000 = 99.5
  3. Apply the integer rule: 99.5 rounds down to 99
  4. Check the spend: 2,000 + 99 × 4,000 = 398,000, within 400,000

Proof, Each Step Named

Compute mode. Let n be the number of functions, a nonnegative integer. The setup fee of 2,000 is charged once, each function costs 4,000, and the budget caps total cost at 400,000. The governing constraint is 2,000 + 4,000n ≤ 400,000. Find the largest n that satisfies it.

  1. Subtraction property of inequality. If a ≤ b then a − c ≤ b − c. Subtracting 2,000 from each side of 2,000 + 4,000n ≤ 400,000 gives 4,000n ≤ 398,000.
  2. Order preserved under multiplication by a positive number. If a ≤ b and c is positive then ca ≤ cb. Multiplying each side of line 1 by one over 4,000, a positive number, gives n ≤ 99.5.
  3. Discreteness of the integers. No integer lies strictly between two consecutive integers. Since no integer sits between 99 and 99.5, an integer n with n ≤ 99.5 satisfies n ≤ 99. Builds on line 2 with the integer condition.
  4. Well ordering principle. Every nonempty set of nonnegative integers has a greatest element under a bound. The largest n meeting n ≤ 99 is 99. Builds on line 3.

Verification. Substitute n equal to 99. 2,000 + 4,000 × 99 = 398,000, at most 400,000. Test 100. 2,000 + 400,000 = 402,000, above 400,000. So 99 holds and 100 fails. She can deploy 99 functions. QED.

The Line on a Plane

Total cost sits at 2,000 + 4,000n. The intercept is the setup fee. The slope is the price per function. The budget is a flat ceiling the line cannot cross.

Cost line 2000 plus 4000n crosses the 400000 budget at 99.5 functions; feasible integer max is 99.

How to read it. The blue line starts at the intercept, 2,000, the cost of zero functions. Each step right adds 4,000, the slope. The red dashed line is the budget. The blue line meets it at 99.5 functions, the yellow point. Since a function cannot be a half, the last whole point under the ceiling is the green one at 99, costing 398,000. That is the answer, option a.

Historical Background

The split between a cost paid once and a cost that grows with each unit is the backbone of cost accounting, a discipline that took shape as factories scaled in the 19th century. Managers needed to know how many units a plant could produce before a budget was exhausted, and the answer always separated setup from throughput. By the early 20th century this reasoning hardened into break even analysis, the standard tool for deciding whether an order, a batch, or a product line paid for itself. Cloud pricing inherited the same shape. A platform fee stands in for the old fixed plant cost, and a per unit charge stands in for the marginal cost of one more item.
