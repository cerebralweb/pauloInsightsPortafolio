THE COMMON UNIT THAT DECIDES HOW MANY IDENTICAL SQUADS YOU BUILD

In this article ❧ Staffing choices often hinge on keeping every group balanced, so no team carries a different mix of skills than the rest. That constraint quietly fixes how many equal groups a manager can form before one skill pool runs short. This problem shows how the greatest common divisor turns a balance rule into an exact group count, and how Python can make that count reusable for any two pools.

The Problem

A software firm has 18 backend engineers and 24 frontend engineers. It wants to split them into project squads for a client rollout. Every squad must keep the same ratio of backend to frontend engineers.

What is the maximum number of squads the firm can form?

  • a) 27
  • b) 6
  • c) 18, with 6 frontend engineers left over
  • d) 9, plus one all frontend squad
Click to Reveal the Answer

Correct Answer: b) 6 ✅

Math Solution

Identical squads force the squad count to divide both 18 and 24 with no remainder, so the answer is the greatest common divisor of the two pools. That value is 6, and each squad then holds 3 backend and 4 frontend engineers.

Same proportion does not mean equal headcount or a 1 to 1 mix. It means every squad shares one fixed ratio, here 3 to 4.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Backend pool: 18 engineers to split
  2. Frontend pool: 24 engineers to split
  3. First division: 24 = 1 × 18 + 6, remainder 6
  4. Second division: 18 = 3 × 6 + 0, remainder 0
  5. Greatest common divisor: last nonzero remainder, 6
  6. Squad makeup: 18 ÷ 6 = 3 backend, 24 ÷ 6 = 4 frontend
  7. Result: 6 squads, each 3 backend and 4 frontend

Formal Proof

Compute mode. Each step names the property that licenses it, then shows that property acting on the numbers.

Setup. Let n be the number of squads, a positive integer. The backend pool holds 18 engineers. The frontend pool holds 24 engineers. Every squad must be identical in makeup, so n must divide 18 and must divide 24. The maximum such n is the governing quantity.

  1. Definition of divisibility. An integer n divides m when m equals n times an integer. So n divides 18 and n divides 24, since identical squads split each pool into n whole shares with no remainder.
  2. Definition of greatest common divisor. The largest integer that divides two integers. So the maximum squad count is gcd(18, 24). Builds on step 1, which fixes n as a common divisor.
  3. Division algorithm. For integers a and b with b positive, a equals q times b plus r with 0 ≤ r < b. Here 24 = 1 × 18 + 6, so the remainder is 6.
  4. Euclidean algorithm invariant. If a equals q times b plus r then gcd(a, b) equals gcd(b, r). So gcd(24, 18) = gcd(18, 6). Builds on step 3.
  5. Division algorithm, again. 18 = 3 × 6 + 0, so the remainder is 0.
  6. Euclidean algorithm invariant, again. gcd(18, 6) = gcd(6, 0). Builds on step 5.
  7. Greatest common divisor with zero. For nonzero d, gcd(d, 0) equals d, since every integer divides 0 and the largest divisor of d is d. So gcd(6, 0) = 6.
  8. Transitivity of equality. If a equals b and b equals c then a equals c. So gcd(24, 18) = 6, which gives n = 6. Builds on steps 4, 6, and 7.
  9. Cancellation law. For nonzero b, b times a over b equals a. So each squad holds 3 backend and 4 frontend, since 18 ÷ 6 = 3 and 24 ÷ 6 = 4. Builds on step 8.

Verification. 6 divides 18 since 18 = 6 × 3. 6 divides 24 since 24 = 6 × 4. No integer above 6 divides both, since 9 fails on 24 and 8 fails on 18. So 6 is the greatest common divisor and the maximum squad count.

Historical Background

The method that finds this shared unit is one of the oldest recorded procedures in mathematics. It appears in Euclid's Elements around 300 BCE, where it was used to reduce ratios of lengths to their simplest form. The same logic still governs practical splitting problems today, from packing goods into equal crates to dividing staff into balanced teams, wherever two counts must break into groups of the same shape.

Python Version

This script finds the most identical squads from any two staff pools, so it works far beyond the 18 and 24 in this problem.

# What this does: finds the most identical squads you can build from two staff pools.
# Where it came from: a firm splits backend and frontend engineers into squads that all share the same mix.
# The math idea: the greatest common divisor, found by repeated division.
# You type in: how many backend engineers and how many frontend engineers you have.
# It prints: the most squads you can form and how many of each role sit in one squad.

# This function finds the biggest number that divides both pools evenly.
def max_squads(backend, frontend):
    # Keep swapping until nothing is left over.
    while frontend != 0:
        # Remember the smaller number.
        old_frontend = frontend
        # New leftover is what backend leaves after dividing by frontend.
        frontend = backend % frontend
        # The old smaller number becomes the new bigger number.
        backend = old_frontend
    # When the leftover hits zero, the last number is the answer.
    return backend

# Tell the reader what we will figure out.
print("Let's find the most identical squads from your two staff pools.")

# Ask for the backend headcount.
backend = int(input("Backend engineers: "))

# Ask for the frontend headcount.
frontend = int(input("Frontend engineers: "))

# Find the squad count.
squads = max_squads(backend, frontend)

# Work out how many of each role sit in one squad.
backend_per_squad = backend // squads
frontend_per_squad = frontend // squads

# Print the answer with words that fit the scenario.
print("Squads you can form:", squads)
print("Each squad holds", backend_per_squad, "backend and", frontend_per_squad, "frontend engineers.")

Run it in a terminal, type the two headcounts, and it returns the squad count along with the fixed role mix inside each squad.
