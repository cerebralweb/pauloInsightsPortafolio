2,940 REQUESTS, ONE RATIO, THREE CLEAN TIERS

In this article ❧ Capacity planning on a GenAI platform starts with knowing how traffic divides across request types. When each type moves in a fixed proportion to a base type, one total tells you every tier without measuring them one by one. This problem shows how a fixed ratio collapses a mixed workload into a single unknown, and how Python turns that logic into a tool you can reuse for any total.

The Problem

A GenAI platform logs requests by type. On average, it handles 3 times as many chat requests as batch requests, and twice as many embedding requests as batch requests. The platform handles 2,940 requests on average.

How many of each type does it handle?

  • a) 980 embedding, 480 batch
  • b) 1,470 chat, 480 batch
  • c) 490 batch, 1,470 chat
  • d) 490 batch, 1,470 chat, 960 batch
Click to Reveal the Answer

Correct Answer: c) 490 batch, 1,470 chat ✅

Math Solution

Call the batch count the base. Chat is 3 times the base and embedding is 2 times the base, so the three types together are 6 times the base. Dividing 2,940 by 6 gives 490, then multiplying recovers 1,470 chat and 980 embedding.

The full split is 490 batch, 980 embedding, 1,470 chat. Option c holds the only correct pairing among the listed choices.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Collect the ratio: batch + 3 batch + 2 batch = 6 batch
  2. Set the equation: 6 batch = 2,940
  3. Solve the base: 2,940 ÷ 6 = 490 batch
  4. Recover chat: 3 × 490 = 1,470 chat
  5. Recover embedding: 2 × 490 = 980 embedding
  6. Check: 490 + 1,470 + 980 = 2,940

Formal Proof

Each step states a finding and names the property that licenses it. Let b be the batch count, a positive integer. Chat is 3b, embedding is 2b, and the three sum to 2,940.

  1. Distributive law. b + 3b + 2b = 6b. The three like terms collect into one coefficient, 1 + 3 + 2, which is 6.
  2. Substitution. The governing equation is 6b = 2,940, replacing b + 3b + 2b with 6b from step 1.
  3. Division property of equality. 6b ÷ 6 = 2,940 ÷ 6, applying the same nonzero divisor to each side.
  4. Cancellation law. The left side reduces to b, since 6b ÷ 6 cancels the 6.
  5. Cancellation law. The right side reduces to 490, since 2,940 ÷ 6 is 490.
  6. Transitivity of equality. Therefore b = 490, from steps 4 and 5.
  7. Substitution. Chat is 3 × 490 = 1,470. Embedding is 2 × 490 = 980, from step 6.

Verification. 490 + 1,470 + 980 = 2,940. The three types sum to the total.

Historical Background

Splitting a whole into parts fixed by ratio is one of the oldest applied calculations. Merchants in ancient Mesopotamia divided harvests and profits by fixed shares recorded on clay tablets, long before symbolic algebra existed. The method survived because it answers a recurring commercial need, which is finding every part of a mix once you know the total and the proportions that bind the parts together.

Python Version

This function takes any total and any pair of multiples, then returns the count for each request type, so it works for future totals without new arithmetic.

def request_split(total, chat_multiple=3, embedding_multiple=2):
    parts = 1 + chat_multiple + embedding_multiple
    batch = total // parts
    chat = chat_multiple * batch
    embedding = embedding_multiple * batch
    return {"batch": batch, "chat": chat, "embedding": embedding}


print(request_split(2940))

Run it with any average total and it returns the three tier counts as a dictionary, printing 490 batch, 1,470 chat, and 980 embedding for 2,940.
