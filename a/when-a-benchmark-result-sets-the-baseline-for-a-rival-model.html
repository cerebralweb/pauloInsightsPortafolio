WHEN A BENCHMARK RESULT SETS THE BASELINE FOR A RIVAL MODEL

In this article ❧ Vendor benchmarks rarely publish both sides of a comparison. One throughput figure is released, the rest of the story arrives as a percentage, and the buyer has to recover the missing baseline before any capacity plan holds. This problem shows how a percentage claim can be inverted into the absolute figure it hides, and why the choice of a common unit decides whether that inversion stays in whole units of work.

The Problem

A cloud provider benchmarked two document extraction models for one minute each. Model D extracted 54 invoices, which was 120% of what Model M extracted.

How many invoices did Model M extract?

  • a) 45
  • b) 49
  • c) 50
  • d) 48
Click to Reveal the Answer

Correct Answer: a) 45 ✅

Math Solution

Model D stands at 120% of Model M, so its 54 invoices carry a rate of 120/100, which reduces to 6/5. Dividing 54 by 6/5, or multiplying by 5/6, returns the baseline of 45 invoices.

A rate of 120% means the two models stand as 6 parts to 5, so every 6 invoices from Model D answer to 5 from Model M.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Percent as a fraction: 120% = 120/100
  2. Reduce the rate: 120/100 = (20)(6)/(20)(5) = 6/5
  3. Write the equation: (6/5)M = 54
  4. Take the inverse on both sides: (5/6)((6/5)M) = (5/6)(54)
  5. Collapse the inverse pair: (5/6)((6/5)M) = (1)M = M
  6. Reduce the right side: (5/6)(54) = (5)(6)(9)/6 = 45
  7. Result: M = 45 invoices
  8. Check: (6/5)(45) = (6)(9) = 54

The Common Unit Route

The same answer arrives by splitting both percentages into equal parts:

  1. Common unit: GCF(120, 100) = 20, so one unit is 20 percentage points
  2. Part counts: 120/20 = 6 parts for Model D, 100/20 = 5 parts for Model M
  3. Size of one part: 54/6 = 9 invoices
  4. Rebuild the baseline: (5)(9) = 45 invoices
  5. Why 20 and not 10 or 5: a unit of 10 gives 12 parts and 54/12 = 4.5, a unit of 5 gives 24 parts and 54/24 = 2.25, so only 20 leaves a part count that divides 54

The Proof, Property by Property

The breakdown above shows the moves. This section names the property that licenses each one, so no step rests on inspection.

Setup

Let M be the invoices Model M extracted and D the invoices Model D extracted. The benchmark fixes D at 54. The comparison fixes D as 120% of M. So D = (120%)M.

Notation

  • D is the invoices Model D extracted, 54.
  • M is the invoices Model M extracted, the unknown, a positive integer.
  • % reads per hundred, so x% = x/100.
  • 120% is the rate that carries D from M, here 120 per hundred.
  • 6/5 is 120/100 in lowest terms, produced in Step 2.
  • 5/6 is the multiplicative inverse of 6/5, used from Step 4.
  • ⇒ reads implies.

Step 1, Definition of percent

Property. Percent. x% = x/100.

Inference. 120% = 120/100.

Step 2, Cancellation law

Property. Cancellation law. For y ≠ 0, (yx)/y = x.

Inference. 120/100 = (20)(6)/(20)(5) = 6/5. From line 1.

Step 3, Substitution

Property. Substitution. x = y ⇒ x may replace y.

Inference. D = (120%)M and D = 54, so (6/5)M = 54. From line 2.

Step 4, Multiplication property of equality

Property. Multiplication property of equality. x = y ⇒ cx = cy.

Inference. (5/6)((6/5)M) = (5/6)(54). From line 3.

Step 5, Multiplicative inverse and multiplicative identity

Property. For x ≠ 0, (1/x)x = 1 and 1x = x.

Inference. (5/6)((6/5)M) = (1)M = M. From line 4.

Step 6, Cancellation law, as in Step 2

Property. Cancellation law, as in Step 2.

Inference. (5/6)(54) = (5)(6)(9)/6 = (5)(9) = 45. From line 4.

Step 7, Transitivity of equality

Property. Transitivity of equality. x = y and y = z ⇒ x = z.

Inference. M = 45. From lines 5 and 6.

Verification

(6/5)(45) = (6)(9) = 54. Both sides match.

Answer

M = 45. Model M extracted 45 invoices, which is option a.

Historical Background

Percentage comparison entered commerce through Italian merchant arithmetic, where profit, loss, and interest were quoted per hundred so that contracts of different sizes could be judged against one another. The unit of one hundred was a convention of the ledger rather than a result, and it survived because it let a clerk restate any ratio without redrawing the accounts.

The inversion in this problem has the older lineage. Recovering a base from a part and a rate is the classic rule of three, which reached European counting houses through Arabic sources and served for centuries in currency conversion, alloy assay, and freight pricing. Technology benchmarking borrows the same procedure whenever a vendor publishes a relative claim and leaves the reference figure out.

Python Version

The script inverts a percentage claim into the baseline figure it conceals, and it returns the part structure that makes the division land in whole units of work.

from math import gcd


def baseline_from_percent(known_output, percent_of_base):
    """Recover the base figure behind a percentage comparison.

    known_output    output measured for the compared item, e.g. 54 invoices
    percent_of_base the compared item as a percent of the base, e.g. 120

    Returns the base output and the part structure that divides it evenly.
    """
    unit = gcd(percent_of_base, 100)
    compared_parts = percent_of_base // unit
    base_parts = 100 // unit
    per_part = known_output / compared_parts
    return {
        "base_output": known_output * 100 / percent_of_base,
        "unit_in_points": unit,
        "compared_parts": compared_parts,
        "base_parts": base_parts,
        "per_part": per_part,
        "whole_parts": float(per_part).is_integer(),
    }


if __name__ == "__main__":
    print(baseline_from_percent(54, 120))

Run it with python baseline.py and it reports a base output of 45.0 invoices, a unit of 20 percentage points, 6 parts against 5, and 9.0 invoices per part.
