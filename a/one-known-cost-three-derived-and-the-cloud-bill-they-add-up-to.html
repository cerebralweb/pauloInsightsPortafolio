ONE KNOWN COST, THREE DERIVED, AND THE CLOUD BILL THEY ADD UP TO

In this article ❧ Cloud bills rarely arrive as four independent figures. One service cost is fixed by a contract or a cap, and the rest are set as shares or offsets of it, so a finance team has to resolve the chain in the right order before it can report a total. This problem shows how a short run of dependent calculations models a real spend review, and how Python turns that logic into a tool the team can reuse each month.

The Problem

A finance team reviews last month's cloud spend across four services. Storage cost 56 thousand dollars before a billing cap paused it. Analytics cost 10 thousand more than Compute. Networking cost half as much as Analytics before it was shut off. Storage cost twice as much as Compute.

What was the combined spend across the four services?

  • a) 140
  • b) 111
  • c) 141
  • d) 84
Click to Reveal the Answer

Correct Answer: c) 141 ✅

Math Solution

Start from the one known figure. Storage is 56, so Compute is half of Storage, 28. Analytics is Compute plus 10, 38. Networking is half of Analytics, 19. Add the four to reach 141.

Each cost waits on the one before it, so the order of the steps is the whole solution.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Storage spend: 56
  2. Compute spend, half of Storage: 56 ÷ 2 = 28
  3. Analytics spend, Compute plus 10: 28 + 10 = 38
  4. Networking spend, half of Analytics: 38 ÷ 2 = 19
  5. Combined total: 56 + 28 + 38 + 19 = 141

Historical Background

The idea that one quantity is fixed by its link to another sits at the heart of how economists model whole systems. In the 1930s Wassily Leontief built input output tables that traced how output in one industry feeds demand in others, a web of dependent figures much like these linked service costs. The approach became a standard tool for national planning and forecasting, and it earned Leontief the Nobel Prize in Economics in 1973.

Python Version

The script resolves the same chain for any anchor cost and any offset, so the team can rerun it each month instead of redoing the arithmetic by hand.

# What this does: adds up last month's cloud spend across four services.
# Where it came from: a finance team knew one service cost and how the others linked to it.
# The math idea: find each cost from a known one, then add them all.
# You type in: the Storage spend and how much more Analytics cost than Compute.
# It prints: the combined spend across the four services.

# This function does the math.
def total_spend(storage, extra):
    # Compute cost is half of Storage.
    compute = storage / 2
    # Analytics cost is Compute plus the extra amount.
    analytics = compute + extra
    # Networking cost is half of Analytics.
    networking = analytics / 2
    # Add the four costs.
    return storage + compute + analytics + networking

# Tell the reader what we will figure out.
print("Let's add up the cloud spend across four services.")

# Ask for the Storage spend.
storage = float(input("Storage spend: "))

# Ask for how much more Analytics cost than Compute.
extra = float(input("Extra amount Analytics had over Compute: "))

# Do the math.
result = total_spend(storage, extra)

# Show a whole number when it comes out even.
result = int(result) if result.is_integer() else result

# Print the answer with words that fit the scenario.
print("Combined cloud spend across the four services:", result)

Run it in a terminal, type 56 for Storage and 10 for the extra amount, and it returns 141.
