THE NUMBER HIDING INSIDE EVERY CLOUD STORAGE BATCH

In this article ❧ Storage decisions in the cloud start long before a single file moves. Teams estimate volume first so they can forecast the bill, check quota headroom, and decide whether to compress or tier the data. This problem shows how one multiplication followed by a unit change turns a file count into a figure the billing console can read.

The Problem

A data team archives log files to cloud object storage. Each log file takes 90 megabytes.

How much storage does a batch of 300 log files use?

  • a) 27 gigabytes
  • b) 270 gigabytes
  • c) 3 gigabytes
  • d) 2,700 megabytes
Click to Reveal the Answer

Correct Answer: a) 27 gigabytes ✅

Math Solution

Multiply the file count by the size of one file to reach 27,000 megabytes. Then divide by 1,000, since cloud billing counts one gigabyte as one thousand megabytes, which gives 27 gigabytes.

The whole answer turns on the billing convention that treats one gigabyte as one thousand megabytes.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Unit size: 90 megabytes per file
  2. Batch total: 300 × 90 = 27,000 megabytes
  3. Convert to gigabytes: 27,000 ÷ 1,000 = 27 gigabytes
  4. Conclusion: the batch uses 27 gigabytes of storage

Historical Background

The gap between a round thousand and 1,024 shaped computing for decades. Early machines measured memory in powers of two, so one kilobyte often meant 1,024 bytes rather than a plain thousand, and the mismatch grew as storage scaled. In 1998 the International Electrotechnical Commission named separate binary units, kibi and mebi and gibi, so that kilo and mega and giga could keep their decimal meaning, which is the convention cloud billing follows today.

Python Version

The script multiplies a file count by a per file size and converts the result to gigabytes, so it handles any batch.

# What this does: works out how much cloud storage a batch of log files uses.
# Where it came from: a data team archives log files to the cloud and needs the total size.
# The math idea: multiply, then change megabytes into gigabytes.
# You type in: how many files and the size of one file in megabytes.
# It prints: the total storage the batch uses, in gigabytes.

# This function does the math.
def total_storage_gb(file_count, file_size_mb):
    # Multiply the file count by the size of one file. This gives megabytes.
    total_mb = file_count * file_size_mb
    # Cloud billing treats 1 gigabyte as 1000 megabytes, so divide by 1000.
    return total_mb / 1000

# Tell the reader what we will figure out.
print("Let's find how much cloud storage this batch of log files uses.")

# Ask for the number of files.
file_count = int(input("Number of log files: "))

# Ask for the size of one file in megabytes.
file_size_mb = float(input("Size of one file in megabytes: "))

# Do the math.
result = total_storage_gb(file_count, file_size_mb)

# Show a whole number when it lands even, otherwise keep the decimals.
result = int(result) if result.is_integer() else result

# Print the answer with words that fit the scenario.
print("Total cloud storage used:", result, "gigabytes")

Run it in a terminal, type the file count and the file size, and it returns the total in gigabytes.

# Cloud Storage Batch Sizer

This skill estimates how much cloud object storage a batch of equally sized files will use. It takes the number of files and the size of one file in megabytes, then reports the total in gigabytes using the decimal billing convention cloud providers apply. It is meant for planning an upload, checking quota headroom, or forecasting a storage bill.

---

## Dependencies

None. This skill uses plain arithmetic and needs no external libraries or tools.

---

## Inputs

- **Number of files**: a whole number. How many files are in the batch.
- **Size of one file**: a number in megabytes. All files are treated as the same size. May carry decimals.

---

## Steps

### Step 1 — Collect the two inputs

Ask for the number of files in the batch and the size of one file in megabytes. Treat the file count as a whole number and the file size as a value that may carry decimals.

### Step 2 — Compute the total in megabytes

Multiply the number of files by the size of one file. The result is the batch total in megabytes.

### Step 3 — Convert to gigabytes

Divide the megabyte total by 1,000, because cloud billing treats 1 gigabyte as 1,000 megabytes. The result is the total in gigabytes.

### Step 4 — Report the result

If the gigabyte total lands on a whole number, show it without decimals. Otherwise keep the decimals. State the answer in plain terms, for example: total cloud storage used, 27 gigabytes.

---

- "Estimate the cloud storage for a batch upload before I send it."

- "How much space will this archive take in the cloud?"
