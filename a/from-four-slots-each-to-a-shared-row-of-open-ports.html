FROM FOUR SLOTS EACH TO A SHARED ROW OF OPEN PORTS

In this article ❧ Layout decisions in a serverless deployment carry a quiet cost. When teams wire functions into one pipeline, they trade external reach for internal flow, and the number of connection points left for clients drops. This article shows how a small counting rule captures that trade, and how Python turns the rule into a tool that works for any number of functions.

Picture a set of serverless functions. Each function has 4 connection slots. Two questions decide how many slots stay open for clients. First, how many functions. Second, whether the functions are chained into one pipeline or kept separate. The two layouts give two different counts from the same functions.

Separate functions are simple. Each keeps all 4 slots, so the free total is 4 times the number of functions. Chained functions form a row. The interior functions bind a neighbor on each side and keep 2 free slots. The 2 end functions bind only one neighbor and keep 3. Add the parts and the row of functions leaves 2 times the count plus 2. For a pipeline of 20, that is 42 open slots, down from the 80 the same functions would offer apart.

The Proof

The chained rule is S equals 2 times M plus 2, where M is the number of functions and S the open slots. The steps below reach the value for M equal to 20. Each step names the property that licenses it.

  1. Substitution property of equality. Equals may replace equals. Replacing M with 20 gives S equals 2 times 20 plus 2.
  2. Distributive law. c times a plus c times b equals c times the sum a plus b. The terms 2 times 20 and 2 share the factor 2, so S equals 2 times the quantity 20 plus 1.
  3. Addition of integers. The inner sum 20 plus 1 equals 21.
  4. Multiplication by two. Two times a number equals that number added to itself. So 2 times 21 equals 21 plus 21 equals 42.
  5. Transitivity of equality. If a equals b and b equals c then a equals c. Therefore S equals 42.

The count is a perimeter. Each join hides two slots, so the row leaves 2 times M plus 2 open.

A separate check confirms it. Interior functions 18 times 2 free slots equal 36. End functions 2 times 3 free slots equal 6. The sum is 42, which matches the rule.

# What this does: works out how many connection slots stay open for clients.
# Where it came from: a team deploys serverless functions, each with 4 slots, and may chain them.
# The math idea: chained functions form a row and share slots at each join, separate ones keep all 4.
# You type in: how many functions, and whether they are chained.
# It prints: the number of free slots left for clients.

# This function does the math for both cases.
def free_slots(function_count, chained):
    # Chained means the functions sit in one row.
    if chained:
        # Interior functions keep 2 free slots, the 2 end functions keep 3.
        # That total works out to 2 times the count, plus 2.
        return 2 * function_count + 2
    # Not chained means each function stands alone and keeps all 4 slots.
    return 4 * function_count

# Tell the reader what we will figure out.
print("Let's find how many connection slots stay open for clients.")

# Ask how many functions there are.
function_count = int(input("How many serverless functions? "))

# Ask whether they are chained. Type y for yes.
answer = input("Are they chained into one pipeline? (y/n): ")

# Turn the y or n answer into a yes or no value.
chained = answer.strip().lower() == "y"

# Do the math.
result = free_slots(function_count, chained)

# Print the answer with words that fit the scenario.
if chained:
    print("Free slots across the chained pipeline:", result)
else:
    print("Free slots across the separate functions:", result)

Run it in a terminal, type the function count, then answer y or n. The script returns the open slot total for the layout you chose, so one program covers both the pipeline and the separate case.

# Serverless Slot Counter

This skill counts the connection slots that stay open for clients across a group of serverless functions. Each function has 4 slots. The count changes with the layout. Chained functions sit in one row and share slots at each join. Separate functions keep all 4 slots each. The skill takes the number of functions and the layout, then returns the free slot total with a short line that fits the scenario.

---

## Dependencies

None. Plain arithmetic only.

---

## Inputs

- **Number of functions** a whole number of serverless functions
- **Layout** whether the functions are chained into one pipeline or kept separate

---

## Steps

### Step 1 — Announce the goal

State that the skill will find how many connection slots stay open for clients.

### Step 2 — Collect the count

Ask how many serverless functions there are. Read the value as a whole number.

### Step 3 — Collect the layout

Ask whether the functions are chained into one pipeline. Accept a yes or no answer. Treat a yes as chained and anything else as separate.

### Step 4 — Choose the rule and compute

If the functions are chained, they form one row. Interior functions keep 2 free slots and the 2 end functions keep 3. This total equals 2 times the count plus 2. If the functions are separate, each keeps all 4 slots, so the total equals 4 times the count.

### Step 5 — Report the result

Print the free slot total with a line that names the layout. For chained, say the slots are free across the pipeline. For separate, say the slots are free across the separate functions.
