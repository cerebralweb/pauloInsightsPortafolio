THE GENAI PILOT SURVEY THAT SETS THE CODE ASSISTANT LICENSE ORDER

In this article ❧ Companies seldom roll out an AI tool to every employee at once. A pilot group tests the options first, and the share of users who prefer each tool guides how many licenses to buy and where to spend on training. This problem shows how a count from a survey becomes a probability, and how that probability supports a license decision.

The Problem

A company ran a GenAI pilot and surveyed the employees in the pilot group on which AI tool they prefer. The chart shows the results.

Based on this survey, what is the probability that an employee from this group names the code assistant as the preferred tool?

  • a) The probability is greater than 50%
  • b) The probability is less than 25%
  • c) The probability is 9%
  • d) The probability is greater than 25% and less than 50%
Click to Reveal the Answer

Correct Answer: d) The probability is greater than 25% and less than 50% ✅

Math Solution

Add the six bars to get the number of employees surveyed, then divide the code assistant count by that total. The result falls in the band of choice d.

Choice c repeats the raw count as a share, so the trap is to skip the division by the total.

Step-by-Step Breakdown

The following sequence shows how the final amount is derived:

  1. Employees surveyed: 9 + 6 + 4 + 5 + 5 + 2 = 31
  2. Employees who prefer the code assistant: 9
  3. Probability: 9 ÷ 31 = 0.2903 → 29.03%
  4. Compare with the choices: 25% < 29.03% < 50% → choice d
  5. Conclusion: an employee from the pilot group has about a 29% chance of naming the code assistant, which is more than 25% and less than 50%

Alternative Method. Listing the Possible Outcomes

Each employee in the pilot group is one outcome. If one employee is picked at random, each of the 31 employees has the same chance. The list below names them E1 to E31 and groups them by the tool they prefer.

There are 31 possible outcomes. The code assistant appears in 9 of them, so the probability is 9/31 ≈ 29.03%, choice d.

A Common Error

An error is to say there are 6 tools, so the chance of the code assistant is 1/6 ≈ 16.67%, which points to choice b. The six tools are not outcomes with equal chances. The code assistant holds 9 of the 31 employees, and image generation holds 2.

The same error appears when one averages the six shares. (9/31 + 6/31 + 4/31 + 5/31 + 5/31 + 2/31)/6 = (31/31)/6 = 1/6. That is the share of an average tool, not the share of the code assistant.

List the outcomes that have equal chances, the employees, then count the ones that match. Tools are groups of outcomes, not outcomes.

Proof With Named Properties

Mode. Compute.

Setup

Let N be the number of employees surveyed, k the number who prefer the code assistant, and P the probability that an employee names the code assistant. The chart gives six counts, 9, 6, 4, 5, 5, and 2, so N = 9 + 6 + 4 + 5 + 5 + 2 and k = 9. The classical definition of probability gives P = k/N. The question asks where P falls among the four choices.

Notation

  • N is the number of employees surveyed, 31 once Step 2 fixes it.
  • k is the number of employees who prefer the code assistant, 9.
  • P is the probability that an employee names the code assistant, the unknown.
  • 9, 6, 4, 5, 5, 2 are the counts for the code assistant, chat assistant, meeting notes, search agent, document drafting, and image generation.
  • 1/100 is the multiplicative inverse of 100.
  • % reads per hundred, so x% = x/100.
  • x, y, z, q, r are any real numbers or integers, used to state a property in general form.
  • ⇒ reads implies.
  • < reads is less than, and ≤ reads is less than or equal to.
  • ≠ reads is not equal to.
  • ≈ reads is about equal to.

Solution

Step 1. Associativity of addition

Property. Associativity of addition. (x + y) + z = x + (y + z), so any grouping of a sum gives the same total.

Inference. N = (9 + 6) + (4 + 5) + (5 + 2) = 15 + 9 + 7.

Step 2. Associativity of addition, again

Property. Associativity of addition, as in Step 1.

Inference. N = (15 + 9) + 7 = 24 + 7 = 31. From line 1.

Step 3. Substitution

Property. Substitution. x = y ⇒ x may replace y.

Inference. P = k/N, k = 9, N = 31 ⇒ P = 9/31. From line 2.

Step 4. Multiplicative identity

Property. Multiplicative identity. (x)(1) = x, with 1 = 100/100.

Inference. P = (9/31)(1) = (9/31)(100/100). From line 3.

Step 5. Definition of division

Property. Definition of division. For y ≠ 0, x/y = (x)(1/y).

Inference. 100/100 = (100)(1/100) ⇒ P = (9/31)(100)(1/100). From line 4.

Step 6. Associativity and commutativity of multiplication

Property. Associativity and commutativity of multiplication. (xy)z = x(yz) and xy = yx.

Inference. (9/31)(100)(1/100) = ((9)(100)/31)(1/100) = (900/31)/100 = (900/31)%. From line 5.

Step 7. Division algorithm

Property. Division algorithm. For integers x and y > 0, x = yq + r with 0 ≤ r < y.

Inference. 900 = (31)(29) + 1, 0 ≤ 1 < 31 ⇒ 900/31 = 29 + 1/31. From line 6.

Step 8. Order preserved under addition

Property. Order preserved under addition. x < y ⇒ x + z < y + z.

Inference. 0 < 1/31 < 1 ⇒ 29 < 29 + 1/31 < 30. From line 7.

Step 9. Transitivity of order

Property. Transitivity of order. x < y and y < z ⇒ x < z.

Inference. 25 < 29 < 29 + 1/31 and 29 + 1/31 < 30 < 50 ⇒ 25% < P < 50%. From line 8.

Verification

(P)(N) = (9/31)(31) = 9 = k. Both sides match.

(9 + 6 + 4 + 5 + 5 + 2)/31 = 31/31 = 1, so the six probabilities sum to 1.

Answer

P = 9/31 ≈ 29.03%, so 25% < P < 50%, choice d. An employee from the pilot group has a 29% chance of naming the code assistant as the preferred tool.

Historical Background

In 1662 John Graunt, a London merchant, published a study of the city's Bills of Mortality, the weekly lists of burials by cause. He counted deaths by cause and turned the counts into shares to estimate risks for the whole population. His work is one of the first uses of observed counts to estimate probability, the method a company applies when it reads a pilot survey to plan a rollout.
